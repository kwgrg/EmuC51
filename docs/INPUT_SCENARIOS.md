# GPIO/UART 输入场景（v1）

用于重复验证同一固件与外部输入，不是脚本执行器。默认关闭；场景导入只准备定义，不改变 CPU。I/O_PORTS 中显式“从干净复位重放”才用当前固件新建 CPU（包括清零 IRAM/XRAM），清除调用历史、断点命中计数和覆盖计数，保留调试配置及覆盖开关；然后使用普通单步、运行、步过或跳出推进。

## 格式与上限

JSON 根字段固定为 `format: "emuc51-input-scenario"`、`version: 1`、`name`、`firmwareSha256`、`events`。名称 1–80 字符；摘要是实际解码后的 BIN/CODE 字节 SHA-256。最多 1024 个事件、文件最多 128 KiB；周期为十进制整数 0–1,000,000,000，必须非递减。同周期按数组顺序稳定投递，不排序、不合并。

- GPIO：`{"cycle":40,"type":"gpio","port":3,"value":251}`。端口 0–3、值 0–255，设置整个端口的外部输入掩码。
- UART：`{"cycle":100,"type":"uart","value":65,"ninthBit":true}`。字节 0–255，第九位必填布尔值，调用现有有界逻辑 RX 接口（REN 关闭时丢弃）。

不接受未知字段、嵌套指令、表达式、JS、循环、负数、小数、字符串数值或超量输入。界面读取前检查文件尺寸；Worker 重新校验定义并核对实际固件摘要。导入失败保留当前 CPU 和已准备场景。

## 时间和调试边界

周期从干净复位的 0 起算，与主机墙钟无关。每次准备推进一个 CPU 执行单元前，按顺序投递 `cycle <= 当前 machineCycles` 的事件，然后进行中断/电源仲裁和指令断点检查。指令或中断响应可以跨越目标周期，事件在**下次尝试推进的边界**投递，记录目标周期及实际投递周期；不拆分指令，不补造晶振采样。运行至当前地址、已完成的跳出或零预算不尝试推进，因此不投递。达到预算/观察点/目标后尚未尝试的事件等待下一次推进。断点检查前的事件即使令指令暂停也只投递一次；因此 GPIO 可先触发中断，再进入其向量断点。

- 暂停/继续、预算、断点和观察点均保留事件游标；暂停时机器周期与事件均不随真实时间推进。
- 取消重放立即停用调度，保留 CPU 和已投递输入（包括 UART 队列），未投递事件不会再发生。取消不等于暂停 CPU。
- 调度启用期间，即使全部事件已投递，也保持输入锁定直到取消；禁止手工 GPIO/UART、内存/寄存器改写及替换场景。允许调试配置和覆盖统计操作。
- CPU 执行故障停用调度并保留已投递日志，修复/重新准备后须显式重放。
- 普通复位停用调度并清空本次日志，保留场景；普通复位沿用原有 CPU 内存语义。再次“从干净复位重放”才保证相同初态。
- 换固件撤下场景。异步校验受取消、复位、执行及换固件的代次保护，不可晚到覆盖新工作区。
- 自动保存/工作区导出包含 CPU 外设状态与绑定的场景定义。刷新或导入工作区恢复已保存 CPU 和定义，但**不恢复启用状态、事件游标或日志**；未投递事件不继续、已投递事件不重发。继续 CPU 是普通执行；再次重放会明确丢弃当前 CPU 状态并从干净初态开始。旧工作区没有场景，保持原行为。
- 掉电不推进周期；未来事件不能唤醒掉电。idle 执行单元仍推进周期并可接受输入唤醒。
- 外部输入本身不计作 CPU 指令、覆盖命中或显式操作数访问；由它引发的中断、固件读取及写入沿用原有调试规则。跳出仍只依据可信调用帧，不因输入投递伪造返回。

## 数字模型限制

GPIO 设置的是外部数字输入，实际引脚仍受端口锁存器影响；同周期先低后高的事件会按现有离散边沿 API 处理，不代表具有电气脉宽的信号。UART 事件仅调用逻辑接收接口；REN 关闭时投递被丢弃，日志不表示接收成功。REN 开启时入队，不表示立即置 RI 或立即接收完成；REN、RI、模式、波特率及第九位过滤沿用外设模型。时间线是输入投递记录，不是总线波形、逻辑分析仪采样或硬件精确时序。

运行热路径在关闭时仅检查一个布尔值；启用时维护顺序游标，不逐步扫描事件数组。日志最多 1024 项，UI 每页 50 项，状态按 Worker 现有刷新节奏发送。

## 可复现示例与验证

源码 [`src/examples/scenario-timer-uart.asm`](../src/examples/scenario-timer-uart.asm)，绑定定义 [`scenario-timer-uart.json`](../src/examples/scenario-timer-uart.json)。也可在 I/O 页面下载源码，在 ASM 工作台导入、构建、加载，然后回到 I/O 点击“准备示例场景”。修改源码导致字节改变时，旧示例摘要将拒绝匹配。

点击“从干净复位重放”，预算设 1500，运行到预算结束：IRAM 30h..33h = `01 1F 42 02`，分别为 INT0 次数、ISR 读取的 TL0、最后 RX 字节、RX 次数；UART TX = `41 42`（AB）。输入目标周期 `[40,44,80,900]`，实际投递周期 `[41,44,80,900]`。T0 是 16 位定时器，T1 mode 2 为 mode 1 UART 提供时钟，INT0 为下降沿；不依赖外部库或编译器。取消后再从干净复位运行，同一预算下 CPU 快照一致。

`tests/core/input-scenario.test.ts` 验证严格格式、上限、同周期顺序、跨指令延后、idle/掉电、REN 和真实程序；Worker 测试验证断点、StepOut、覆盖计数、自动快照、输入互斥、换固件及异步取消；持久化测试验证绑定和恶意内容拒绝；组件测试验证读取前限额、取消晚到文件和分页；Chromium 验证完整重放、重复/取消、刷新/导入恢复、错误隔离、导航及移动布局。

场景定义随 v4 工作区保存，调度状态不加入 CPU v2 快照。本批未实现通用脚本、物理串口、采样波形、多文件工程或源码符号调试。
