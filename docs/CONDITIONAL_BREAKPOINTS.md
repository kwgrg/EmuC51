# 条件断点

在 DEBUGGER 的地址断点行填写条件，Enter 或“应用”同时提交条件和 N；Escape 取消当前输入框草稿。空条件表示始终成立。停用断点保留条件；删除断点删除所有关联配置。运行期间不能修改。

条件复用 [Watch 整数表达式](WATCH_EXPRESSIONS.md)，新增 `== != < <= > >=`，比较返回 0 或 1，非零（包括负数）为真。每项最多 256 字符、128 词元、解析递归 16 层。支持寄存器、SFR 锁存值和显式内存空间；不执行 JavaScript，不允许赋值或函数调用，不支持源码变量。`&&` / `||` 暂不支持；可用带括号的比较结果按位组合，如 `(ACC >= 2) & (R0 != 0)`，两侧都会求值，不短路。

执行顺序：

1. CPU 先处理掉电、idle 和中断进入。仅即将真正执行指令时检查该 PC 的断点；idle 和中断响应单元不求值、不计数。中断处理程序内的指令照常检查。
2. 禁用断点不求值。条件为假时不计数，保留此前累计的真条件次数。
3. 真条件累计到 N 次时在执行该指令前暂停并将该地址计数归零。例如 `INC A; SJMP 0`，PC=0、`ACC >= 2`、N=2，首次停在 ACC=3，继续后停在 ACC=5。
4. 普通断点停止后的继续只绕过一次原地址指令，不再次求值或计数；若先响应中断，绕过保留到原指令实际执行。单步不检查断点；显式 Step Over/Out 的起点沿用已有绕过规则，内部指令检查条件。运行至地址抵达目标时先停止，不执行目标指令。

条件语法错误、未知名称、地址越界、除零、溢出等不会当作假条件。以 `BreakpointConditionError` 停止，显示地址、条件和错误；CPU 不执行这条指令，不消耗命中次数，已完成的 trace 和调用帧保留。此类停止不会获得自动绕过：再次“运行”会重试并再次报错，直到用户修正/禁用条件、改变相关值，或明确单步执行。修改任一条件、启停或 N 会重置该地址计数；重复提交相同规范化配置保留进度。

SFR 求值绕过外设读取钩子，不消耗串口数据、不确认中断，不触发内存变化观察点。端口读取的是锁存值，GPIO 引脚输入仍在 GPIO 面板查看。

## 保存与兼容

条件存入工作区 **v4** 的 `breakpointOptions[].condition`，CPU 快照仍为 v2。新版本可导入 v1/v2/v3：缺省条件始终成立，保留已有启停、阈值、Watch 和内存浏览设置；不恢复临时命中计数、调用历史、运行目标或错误结果。复位/替换固件保留配置并重新计数。

v1–v3 标记的文件不得带有效条件，否则拒绝导入，避免静默改变语义。旧应用不支持完整恢复 v4；请使用新版导入。条件的类型/长度在导入时校验，表达式依赖机器状态的错误在实际到达断点时明确报告，禁用的错误条件不会阻止运行。

最多 1024 个断点；为容纳所有 256 字符条件最坏 JSON 转义后的体积，工作区 JSON 上限为 **4 MiB**（以 UTF-8 字节及文本长度校验）。最大配置导出/导入已有往返测试。BIN 64 KiB、HEX 源文件 1 MiB 和 CODE 64 KiB 限制不变。
