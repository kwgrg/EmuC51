# 最小 C / SDAS8051 混合工程

这是**外部原生构建 → 本地原子包导入 → 模拟器调试**闭环。浏览器不编译 C 或 SDAS，不上传源码，没有后端或费用。原来的浏览器简化 ASM、KEIL A51 与 SDAS8051 不是同一方言，不能直接互换。

## 可运行样例

[完整工程](../tests/fixtures/sdcc-mixed/project/project.json)包含 `src/main.c`、`src/compute.c`、`asm/bridge.asm`、`include/shared.h`。使用经核验的 **SDCC 4.5.0 #15242 (Linux)** 和同发行版 `sdas8051`，Node **22.18+**（原生 TS 类型擦除；本次 Node 24）：

```sh
SDCC_BIN=/path/to/sdcc node scripts/build-sdcc-project.mjs tests/fixtures/sdcc-mixed/project/project.json /path/to/new-output
```

输出目录必须不存在。成功后选择其中唯一的 `emuc51-project.build.json`，在应用「导入外部 SDCC 产物」导入。可直接试用[已验证包](../tests/fixtures/sdcc-mixed/emuc51-project.build.json)。运行 1000 个执行单元后：shared=10、word_result=4864（0x1300）、main 文件静态 shadow=10、compute 文件静态 shadow=3。

构建流程：复制清单中的文件至新的临时目录；每个 C 用相同参数先 `sdcc -S` 生成汇编和 CDB（允许在汇编前检查文件指令），再用 `sdas8051 -plosgffwy` 分别生成 REL；手写 SDAS 也独立汇编；最后 SDCC 驱动按**入口 REL 最先**链接。与一条 `sdcc -c` 自动汇编链相比，此处显式拆开以便检查生成的汇编。所有阶段成功后才在输出父目录写暂存包并原子重命名，异常清理临时目录，不发布部分包；已有输出一律拒绝，不把上次成功产物标成本次结果。

## 项目清单与受限构建

`format=emuc51-sdcc-project, version=1`；必填 `entry`、`sources[{path,language}]`、`headers`、`includeDirs`、`options`。入口是定义 main 的 C 文件，语言仅 `c` 或 `sdas8051`。清单不接受任意命令、工具路径、用户编译/链接参数或额外字段。

固定参数：`-mmcs51 --model-small --iram-size 128 --debug`。不启用 stack-auto、其他内存模型或寄存器组约定。4.5.0 的 mcs51 实测不接受通用帮助中其他目标列出的 `--sdcccall`；本工程采用该固定目标的默认约定，不附加无效参数。

- 最多 16 个源文件、16 个头文件、8 个包含目录；源文件与头文件都必须是清单内的规则文件，拒绝符号链接。
- 路径必须使用有界 ASCII 相对路径和 `/`，拒绝绝对路径、盘符、反斜杠、空段、`.`/`..`、转义路径和 shell 字符。CDB 丢弃目录，因此文件 basename 必须唯一；源模块 stem 也唯一，禁止保留 stem `firmware`，不能把 `a/foo.c`、`b/foo.c` 当成可区分模块。
- 每文件最多 65536 字符/8192 行，合计最多 512 Ki 字符；单包最多 2 MiB，IHX/CDB 各最多 256 KiB，CDB 最多 16384 条记录/8192 个行地址，符号合计最多 4096、函数最多 256。
- C 包含仅允许字面量清单头文件，以及固定安装提供的 `<8051.h>` / `<stdint.h>`。不支持 include_next、宏计算的 include、pragma、续行指令、trigraph/digraph、`_Pragma`、`__has_include`。这些是初版明确的保守语法范围，不是完整 C 预处理器替代品。
- SDAS `.module` 必须匹配文件 stem。初版允许的伪指令为 `.module/.globl/.area/.org/.db/.dw/.ds/.equ/.end`（`.optsdcc` 仅允许编译器生成的汇编）；禁止汇编 include/incbin、宏及其他指令。C 生成汇编也检查后才交给汇编器。C 的普通常量宏/条件编译可用；不支持伪装文件指令。
- 进程通过参数数组执行，不拼 shell 命令；编译/汇编/链接有时限和输出上限，在新的工作目录运行，不继承用户 CFLAGS 或 SDCC 路径覆盖环境。工具本身来自用户明确配置的可信本地安装，不从包里执行程序。

这不是任意恶意原生编译器或编译器漏洞的安全沙箱。用户须信任本地编译器安装；包的摘要证明文件一致性，不是编译器数字签名。固定 SDK 头文件和运行库来自同版本安装，不从项目提供任意库或链接脚本。

## 本次真实 ABI 证据

以 4.5.0 实际生成的汇编、最终链接字节和 CPU 执行回归为准，未把较新在线手册细节直接套入。

| 已证明组合 | 样例与约定 |
| --- | --- |
| C 调用外部 SDAS，8 位首参数/返回 | C 名 `asm_add` 对应 `.globl _asm_add`；DPL 传入 5，汇编加 2、写 `_shared` |
| C→ASM→C 嵌套 | `_asm_add` 通过 LCALL 调 C `_finish`；C 加文件静态 shadow=3，经 DPL 返回 10；RET 逐层返回 |
| 16 位首参数/返回 | `_asm_word` 的 DPL 为低字节、DPH 为高字节，0x12FF 加 1 后返回 0x1300；C 正确存入 word_result |
| 栈平衡与全局访问 | 真实至少三层调用帧；返回循环后 SP 与进入 main 时一致，帧全部弹出；汇编用 `_shared` 访问链接后的 DATA 全局 |

样例未声明 `__naked`、callee-saves、`__using`、reentrant、banked 等特殊 ABI。只证明上述普通外部函数组合，不承诺自动验证任意手写汇编的寄存器保存义务。样例只主动使用 A、DPL、DPH/进位与正常 CALL/RET，不改 SP、PSW 寄存器组或 `_bp`。多参数默认参数区、reentrant 参数栈、bit 参数、32 位返回、ISR 跨语言调用及自定义保存约定属于尚未验证的扩展；不猜测、自动改写或生成这些桥接代码。

## 跨文件导入与调试

包使用 SDCC 调试清单 version 2，包含项目配置摘要、每个源/头文件原始文本与摘要、入口文本、完整链接 IHX/CDB 与摘要。导入和工作区恢复重新核验全部内容及实际固件 SHA，再一次性替换状态；篡改、缺失、不匹配或取消不替换当前 CPU。version 1 四文件导入继续兼容；旧版应用不认识 version 2，不能保证恢复混合调试信息。

多模块 CDB 原样保留：`M:` 分隔 C 声明模块，公共链接地址在最终链接后解析。相同全局在多个模块中的声明保留来源；类型/位置冲突时禁止观察，不任意选一个。两个同名文件静态对象使用 `CDB::<module>::F<module>$name$level$block` 区分。CDB 函数 F 的空间 C/Z 都须有完整已验证起止链接才能命名，汇编缺少 F 记录时不猜函数名。

- 「工程源文件」切换 C、SDAS、头文件的只读内容。同一行号不会跨文件合并；手动选择的源码目标在文件切换、取消和新包导入时失效。
- C 行来自精确 L:C 链接，同时要求对应 C 模块的真实 L:A 指令；目录仅由唯一清单映射，不根据 PC 最近地址猜行。头文件若无行记录则只读展示，无断点。
- 手写汇编 L:A 行只有位于显式 CODE 区、源码直接指令助记符与链接字节一致且指令完整时可用；伪指令、CODE 数据、标签、未知区、宏不变成断点。C 生成汇编的 L:A 行号不当作用户 C 行。
- 「定位当前源码行」可跨文件切换；若多个文件有同一精确地址，优先当前文件，否则按清单首个匹配文件。行断点仍为已记录的地址集合，不是 C 语句步进；`--debug` 不关闭优化，跨行语句不保证每个物理行都有地址。
- 源文件选择和派生表不持久化；刷新回到入口文件，重新验证包再显示源码/符号。项目源文件、头文件、原始调试数据随现有工作区导入导出保存。输入重放、覆盖和旧异步结果继续遵守原有固件替换屏障。

## 验证与后续

原生测试通过 `SDCC_BIN=/path/to/sdcc npm test -- tests/native/sdcc-project.test.ts` 执行。未设置 SDCC_BIN 时明确跳过两项需要编译器的测试；路径/命令拒绝测试仍运行。真实包独立重建逐字节一致，编译失败不生成输出，既有目标不覆盖；核心及浏览器测试覆盖 ABI、同名静态、C/SDAS 行断点、源文件切换、移动宽度、工作区恢复和篡改拒绝。
