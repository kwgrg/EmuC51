# EmuC51

EmuC51 是一个使用 Rust 编写的经典 Intel 8051/MCS-51 指令级模拟器项目。

> **项目状态：早期开发骨架。** 当前仓库还不能执行 8051 固件。本文档会明确区分已经存在的代码与计划实现的能力，避免将路线图误认为当前功能。

## 当前状态

以下状态以 **2026-07-28** 的仓库内容为基线。

已经存在：

- 裸二进制文件读取的最小实现；
- 由内部、外部两段组成的程序存储器原型；
- 128 字节内部 RAM、SFR 和 64 KiB XRAM 的数据结构原型；
- 直接、间接、位和外部寻址的部分只读逻辑；
- 操作码和操作数函数类型的初始结构；
- 两个用于早期实验的二进制文件。

尚未实现：

- 8051 CPU 状态、复位、取指、译码和执行循环；
- 存储器写接口和完整的寻址错误处理；
- 任何可验证的完整指令语义；
- 256 项操作码译码表；
- 可供用户使用的命令行界面；
- 单元测试和固件集成测试。

当前 `src/main.rs` 只是使用硬编码测试路径读取并打印二进制内容，不是目标命令行工具。`cargo test` 能完成构建，但当前没有实际测试；严格 Clippy 检查也尚未通过。

## v1 目标

第一版以“正确执行经典 8051 程序”为核心，计划支持：

- 加载不超过 64 KiB 的裸二进制固件；
- 16 位 PC，以及 ACC、B、PSW、SP、DPTR；
- 四组 R0–R7 工作寄存器；
- 128 字节内部 RAM、标准 SFR、位寻址、64 KiB CODE 和 64 KiB XRAM；
- 经典 8051 的 255 个有效操作码编码；
- 单步执行、有限步数连续执行、名义机器周期统计和状态查看；
- 命令行固件运行、指令跟踪和最终状态输出；
- 存储器、指令和固件三个层次的自动化测试。

详细的范围、架构决策、接口、阶段和验收标准见
[实施计划](docs/IMPLEMENTATION_PLAN.md)。

## v1 不包含

- Intel HEX 文件；
- 精确时钟波形或总线时序；
- 定时器、串口和 GPIO 的完整硬件行为；
- 中断控制器、外部中断和中断优先级；
- 8052 的上层内部 RAM 和定时器 2；
- 断点、观察点、交互式调试器或图形界面；
- Keil 调试信息和源码级调试；
- 厂商扩展 SFR 或扩展指令。

标准 8051 外设 SFR 仍计划作为可读写的被动寄存器存在，但 v1 不驱动相应外设行为。

## 开发命令

在仓库根目录执行：

```console
cargo build
cargo test
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

目前后两个质量检查不一定通过，它们是后续开发的目标门禁，不代表当前基线已经满足。

目标 CLI 完成后，预期用法如下；这些命令当前尚不可用：

```console
c51-sim firmware.bin
c51-sim firmware.bin --pc 0x0000 --max-steps 100000
c51-sim firmware.bin --trace
```
